# 基线实现与实验口径

八个方法都由 `rsi/baseline_suite.py` 调度。实验在同一个任务流中比较环境反馈后的即时修正与跨任务更新。论文方法在本包中属于对照变体。完整论文指标仍需在原论文模型、任务及配置下运行。

| 入口参数 | 读入与更新 | 与原方法的差别 |
|---|---|---|
| `frozen` | 维持初始规则，直接执行任务 | 固定能力下界 |
| `no_reflection_writeback` | 直接根据轨迹与反馈选择更新，用校准集验收 | 与完整反思共享决策后缀及验收逻辑 |
| `reflect_writeback` | 生成反思后选择更新，用校准集验收 | 机制实验对应的主方法 |
| `rise_retry` | 用上次尝试、反馈和反思选择一个临时动作，重跑同一任务 | 借鉴多轮修正。使用冻结模型，原论文的参数训练阶段未复现 |
| `reasoningbank_memory` | 把成功重试的反思和动作写入经验库，按查询、轨迹、反馈的词面相似度检索后提供给模型 | 用哈希词向量近似检索，保留成功重试，原版记忆归纳和测试时间扩展未复现 |
| `gepa_prompt` | 一次反思生成候选操作排序，从声明式规则候选中挑选通过校准的版本 | 用受限候选搜索表达反思引导的更新。自由文本 Prompt 变异、GEPA Pareto 搜索未复现 |
| `godel_sequential` | 生成一项更新，在触发该更新的任务上重试。重试成功即把规则持久化 | 单谱系、声明式自更新。未复现程序自修改 |
| `dgm_archive` | 从可用版本档案选择父版本，评估子版本、写入档案，部署校准成绩最佳的版本 | 复用了论文 Appendix C.2 的父代采样思路，搜索对象限于规则集合，程序自修改和 SWE-bench 评估未复现 |

哈希向量使用归一化的词频特征，不训练 IDF 权重。机制实验的离线最近邻对照另用训练集拟合的 TF-IDF。

## 对照如何公平比较

任务流、校准集、留出集的 case ID 互不重叠。每种方法从相同初始状态开始。校准只用于选择更新。留出评分按四种条件分别计算，作为监测结果，不参与更新选择。由于各集合共享购物篮生成器，留出属于同模板的新案例。正式实验可扩展到独立模板或不同任务族。

- `stream_first_attempt_success` 衡量遇到任务时，当前持久状态能否立即完成。
- `stream_within_task_success` 允许使用同一任务的反馈重试。只影响本任务的改进体现在这里。
- `final_holdout_by_scenario` 衡量持久规则的单次执行能力。此指标只运行规则执行器，记忆检索和允许重试的基线仍需查看任务流中的最终成功率。
- `cost` 记录反思次数、决策前向次数、校准环境调用、重试和父代回放。默认配置统一候选上限，各方法的实际调用数可以不同。
- `dgm_versions.json` 记录版本 ID、父版本、规则、产生该版本的动作和校准分数。每轮另存父代 ID、部署前后 ID。相同的规则集合只入档一次。

正式比较可分别固定模型调用数、候选校准调用数或 Token 预算。默认实验中规则只追加，任务间几乎无冲突，不能据此评估灾难性遗忘。若研究持续学习，可加入跨域相反规则、任务间干扰、写回前后分场景回归测试。
